# ADR-005: The wasm boundary (Phase 5)

## Status

Done. `crates/palsave-wasm`, plus `crates/palsave/src/guilds.rs` for the logic it
binds to. Six `wasm-bindgen-test` cases green in a real wasm runtime, including the
phase gate: open → edit → export.

## Keeping the wasm crate logic-free

`CLAUDE.md` requires `palsave-wasm` to be a binding shim, so the guild operations the
plan lists as its API (`list_guilds`, `guild`, `set_guild_name`) can't live there.
They went into a new `palsave::guilds` module: a task-level layer composed from the
container / gvas / rawdata / edit layers below it, testable with plain `cargo test`
and no browser. Every function in `palsave-wasm` is now three lines — convert
arguments, call one `palsave` function, convert the result.

That split paid for itself immediately: `guild_api_round_trips_on_level_sav` exercises
list → detail → rename → re-encode → reopen against the real 8.5 MB `Level.sav` in
about a second, natively. None of that needed a wasm toolchain to develop.

## Handles, not trees

`SaveHandle` owns the decompressed GVAS `Vec<u8>`; JS gets an opaque handle. Reads
return view models sized by *what was asked for* — a guild list, one roster — never
by save size. `export()` is the one exception, and it's called once.

`SaveHandle` deliberately does **not** hold a parsed `GvasFile`. `GvasFile<'a>`
borrows from the buffer, so storing both would make `SaveHandle` self-referential.
Re-parsing per call is the alternative, and it's genuinely cheap: `GvasFile::parse`
walks only the top-level property list, skipping each value by its `size` field — 4
properties for `Level.sav`. Paying that on each call is far better than fighting the
borrow checker with `Pin`/unsafe for a lazy parser that was designed to be re-run.

An edit *replaces* the buffer rather than keeping the original alongside it. wasm32
has a 4 GB address-space ceiling and `Level.sav` decompresses to ~8.5 MB; a handle
that accumulated a copy per edit would be a real problem on a large server save.

## Two things that would have been silent bugs

**`FDateTime` ticks cross as a string, not a number.** `last_online_real_time` is
~6.8×10¹¹ today, under 2^53 — but it's an `i64` and JS numbers lose integer precision
above 2^53. Sending it as a `number` would work now and corrupt data later, which is
exactly the failure class `CLAUDE.md` cites for choosing Rust. It crosses as a decimal
string; `save-types.ts` tells callers to use `BigInt` for arithmetic.

**`export()` verifies before returning.** It runs `edit::verify_reparses` on the
buffer first and errors rather than returning bytes that don't re-parse. A caller may
be about to overwrite a real save with these bytes.

## Errors

Every error crossing the boundary is `{ code, message }`. `code` is a stable
machine-readable discriminant (`GuildError::code()` in `palsave`, extended with
container/parse/serialization codes in the shim); `message` is display-only. The full
union is enumerated in `src/lib/save-types.ts` so the UI can exhaustively match.

## Testing: Node, not headless Chrome

The plan specifies `wasm-pack test --headless --chrome`. No browser or webdriver is
installed in this environment, and these tests touch no DOM or Web API — only
wasm-bindgen marshalling — so they run under `wasm-pack test --node` (`npm run
wasm:test`) instead. That's a real wasm runtime exercising the real boundary; the
browser runner would add a webdriver dependency without covering anything more. A
comment in `tests/boundary.rs` says how to switch if a future test needs a browser.

The tests build their save synthetically rather than reading `fixtures/` — fixtures
are gitignored and a browser test couldn't read them anyway. Format correctness is
covered against real saves by `palsave`'s native fixture tests; these prove the
boundary.

## Build

`npm run wasm` → `wasm-pack build --target web --out-dir src/lib/wasm --release`
(324 KB `.wasm`). `npm run dev` / `npm run build` run it first. `src/lib/wasm/` is
gitignored. Single-threaded, no rayon — COOP/COEP headers can't be set on static
hosting.

`tsconfig.app.json` excludes `src/lib/wasm/**`: wasm-pack's glue JS isn't written to
pass `checkJs`, and it's generated output nobody should be editing. Its own generated
`.d.ts` is accurate and is what consumers use, alongside the hand-maintained view-model
types in `src/lib/save-types.ts`. Those mirror the `#[derive(Serialize)]` structs by
hand — nothing enforces that automatically, so they change together.
