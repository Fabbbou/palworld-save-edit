# Contributing

## Layout

```
crates/palsave/       pure Rust core — no wasm-bindgen, testable with `cargo test`
  src/container/      PlZ / PlM / CNK compression
  src/gvas/           lazy GVAS reader + byte-exact writer
  src/rawdata/        Palworld-specific RawData decoders, one module per path
  src/edit/           splice engine
  src/guilds.rs       task-level API the wasm layer binds to
  src/bin/sniff.rs    native CLI: identify a .sav container without decompressing
  examples/           dev tools for poking at real saves (inspect, drill, explore, …)
crates/palsave-wasm/  wasm-bindgen bindings — shim only, no logic
src/                  Svelte 5 app
  lib/worker/         module worker hosting the wasm
  lib/wasm/           wasm-pack output (gitignored, regenerated by `npm run wasm`)
fixtures/             real .sav files — GITIGNORED, never commit
```

Architecture decisions live in `ADR-00*.md`. Read `CLAUDE.md` first — the boundary
rule and the round-trip requirement are non-negotiable.

## Running things

```bash
cargo test --workspace              # native tests (fixture tests skip if fixtures/ is empty)
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all

npm run wasm                        # build the wasm package into src/lib/wasm/
npm run wasm:test                   # wasm-bindgen boundary tests, under Node
npm run dev                         # wasm (dev profile) + vite dev server
npm run build                       # wasm (release) + vite build
npm run check                       # svelte-check / tsc
```

`cargo run --bin sniff -- path/to/Level.sav` prints a save's container header without
decompressing it. Useful first step when something won't open.

## Adding a fixture for a new game version

This format is undocumented and moves with the game. Fixture tests are the only thing
standing between a format change and a corrupted save, so when a new Palworld version
lands:

1. Drop real saves into `fixtures/` — at minimum `Level.sav`, ideally also
   `LevelMeta.sav`, `WorldOption.sav`, and a `Players/<uid>.sav`. See
   `fixtures/README.md`.
2. Run `cargo test --workspace`. The tests in `crates/palsave/tests/fixtures.rs`
   auto-discover every `.sav` under `fixtures/` — there's no list to update.
3. If a round-trip test fails, **do not** adjust a decoder until you know why.
   `cargo run --example drill -- fixtures/Level.sav worldSaveData.GroupSaveDataMap`
   and friends will show you where the bytes stop making sense.

**`fixtures/` is gitignored and must stay that way** — real saves contain SteamIDs
and player names. That's also why CI's fixture tests self-skip: they check the file
exists and return early. The synthetic tests are what CI actually exercises; the
fixture tests are the local gate before you push a format change.

## When a format detail is unknown

Don't guess. A plausible-looking wrong answer here destroys 200-hour worlds. The
established pattern, used throughout `rawdata/`, is:

- decode into a typed struct, and assert the decoder consumed **exactly** the blob
  (`RawDataError::NotExhausted`), or
- keep the region as opaque bytes and pass it through untouched.

Both are correct behaviour. A half-parsed blob is not. ADR-002.md is a worked example:
the reference implementation everyone else uses had drifted out of date, the decoder
failed closed rather than producing garbage, and the fix came from finding a
maintained implementation — not from guessing at the bytes.

## Style

`cargo fmt` and `cargo clippy -D warnings` both gate CI. Comments should explain *why*
something is the way it is — especially anything that looks arbitrary, since most of
this codebase is reverse-engineered and the reasons aren't recoverable from the code.
